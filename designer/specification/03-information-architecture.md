# Information architecture and interface surfaces

**DDN Designer specification 0.2.0 — proposed; baseline audited 0.7.0.**

## Application separation
`live/editor.html` remains Studio, the source-first application. `designer/index.html` becomes Designer. A top-level project navigation may link both, but neither route redirects to or replaces the other. Open source in Studio is an explicit handoff with a workspace snapshot, selected view and stable selection. If a second window is used, the receiving editor reports its base revision; automatic cross-tab write merging is not assumed.

## Main desktop layout
Target a comfortable 1440×900 working surface. Reference dimensions are design tokens, not fixed page geometry: 56px project bar, 44px tools/view bar, 240px left shelf, 320px inspector, 28px bottom status. The canvas takes the remainder. At 1180px the shelves become collapsible; at tablet widths use one shelf at a time. Phone support initially permits inspection and property edits, not a desktop canvas squeezed to illegibility.

The project bar contains project name, save/draft status, undo/redo, source handoff, Review, and Export. The tools bar contains Select, Pan, Connect, Add, view tabs, and Arrange. Look, palette and print settings are inside This view, not spread across the top. Search is reachable without opening a large toolbox.

## Left shelf
Three tabs: **Add**, **Model**, **Views**. Add offers the current profile's common items and search of the installed registry. Model displays definitions, their files/data blocks and usage. Views displays named projections and child references. Switching tabs does not change data.

Add never shows 188 equally weighted shapes. The initial generic shelf has eight task groups: Meaning; Data; Process; Systems; Scopes; People & control; Notes & evidence; Analysis. A specialized profile shows 6–12 relevant templates. “All installed” and exact-name search retain discoverability. Favorite templates are user preferences, not new semantic kinds.

> Implementation status (ED-001): the full 333-kind mapped shelf is implemented in `designer/prototype/` — the Add tab renders the eight `palette_group` sections and every kind from `contracts/kind-ui-map.json` with search and per-kind `creation_action` dispatch. Profile-filtered specialized shelves remain proposed.
>
> Implementation status (2026-10 redesign, phase 2): in the live unified tool (`notation/tool/src/`, `?mode=design`) the Add palette is now capability-filtered. Every contract kind/relation carries a generated `allowed_in` list (capability tags: projection kinds + profile ids; derived by `notation/runtime/ddn-capabilities.js` from the merged registry and the profiles catalogue, stamped by `designer/contracts/build-allowed-in.mjs`). Unprofiled graph views offer the generic kinds grouped under the eight task groups; a profiled graph view offers only that profile's vocabulary (plus validator-backed participants, e.g. flow.* symbols under `bpmn.*`/`uml.activity@*`); data-bound projections show no element palette — a hint points to the Source drawer instead. The "All installed kinds" toggle and exact-name search remain as escape hatches. The palette filters what it offers; DDN source stays permissive and validation is unchanged.

## Right inspector
Selection header: friendly name, semantic kind, source location, and “Used in n views.” Three tabs remain stable:
- **Meaning:** identity-independent name, kind, meaningful content and required profile properties.
- **This view:** visible compartments, approved appearance variants, pin/size/route settings, occurrence notes and local overrides.
- **Details:** typed implementation, scope, evidence, domain and extension groups with search.

Without a selection the inspector shows the selected view's projection, profile, layout, appearance and publication. Multiple selection exposes only compatible controls, including a mixed-value state; it never replaces distinct meanings with whichever value was read first.

> Implementation status (2026-10 redesign, phase 1): in the live unified tool (`notation/tool/src/`, `?mode=design`) the right shelf now splits into exclusive **Document** and **Style & Layout** drawers, and the no-selection case is wired: deselecting (empty-canvas click or Escape) opens the Document drawer — publication, chrome, legend, header/footer run bands, page border/background and view metadata, all written into the source view block through the authoring channel — while selecting an element opens the inspector (still hosted in the Source drawer until phase 3). Style & Layout carries the view's style/layout/display settings with per-group write-scope labels ("View override (saved to source)" vs "Session preview (not saved)"). Multiple-selection controls and the stable Meaning/This view/Details tab structure remain proposed.
>
> Implementation status (2026-10 redesign, phase 3): the inspector is now its own right-side **Inspector** drawer in the exclusive set {Document, Style & Layout, Inspector}: selecting an element or relation opens it (closing the other two), deselecting returns to Document; the Source drawer carries text editing + diagnostics only. The inspector is structured as the stable three tabs — **Meaning** (shared definition: label, capability-agnostic kind dropdown, description, x_icon picker, fields list with an inline add-field form, "Used in n views" header with a shared-scope impact note when n > 1, source location, Go to source / Duplicate / Delete), **This view** (occurrence: pin X/Y + pin/unpin, hide, session-preview relation routing), and **Details** (read-only grouped property display from the parsed definition, grouped per `standard/registry/data-properties.json`, with edit-in-source jumps — descriptor-form editing remains a later phase). Relation selections add the spec-05 controls on the Meaning tab: verb dropdown filtered by endpoint-pair legality, per-end min/max cardinality with the live sentence preview, enforcement, scope, endpoint marks, and UML association-end role/multiplicity/qualifier. Multi-selection (when the canvas reports several source ids) shows the intersected surface with mixed-value reporting and never offers single-identity edits; the canvas gesture for multi-select remains proposed.

## Bottom surfaces
A collapsed Problems strip reports error, warning and incomplete counts separately. Expanding opens a navigable list tied to elements/fields and fixes. An optional source-diff drawer shows the last command's exact changed ranges and affected views. The status line distinguishes “Saved in browser,” “Downloaded,” and “Saved to selected file”; a local cache is not a disk-save guarantee.

> Implementation status (2026-10 redesign, phase 5): the bottom shelf now holds two exclusive drawers — **Source** (text editing + diagnostics) and **Type sheet** (the diagram-type editing surface, `notation/tool/src/sheets.js`). The Type sheet joins the drawer-state system (`?drawers=typesheet:…`, the settings popup, mode presets) and dispatches its body by view capability (projection kind + profile, reusing the phase-2 capability model): a view whose profile has a registered body auto-opens the drawer, a plain graph view auto-closes it, and an explicit user open/close overrides the automation until the view changes. The first registered body is the **CMMN case-plan sheet** (`cmmn.basic@1`/`cmmn.complete@1`): a case-plan outline tree (stage frames scope their members; unframed items sit at the case root) with add-stage/task/milestone/case-file/sentry and reparent/remove/delete operations, a sentry editor (`x_sentry`: on/attach/on_part/if_part), tri-state decorator flags (`x_cmmn`), and a reorderable planning-table editor (`x_planning`). Every write is one guided, undoable, core-validated authoring transaction (`authoring.setElementExtension` — new, mirroring `setRelationExtension` — plus the new `setFrameMembers`/`addFrame` view-frame channels). Tree selection and canvas selection sync both ways. Remaining type-sheet bodies (UML, chart, matrix, decision, timeline, fishbone, panels, BPMN) are phase 6.
>
> Implementation status (2026-10 redesign, phase 6a): five more Type sheet bodies are registered: **UML structure** (`uml.structure@1`/`@2` — per-classifier member table with `x_member` kind/visibility/static/abstract/derived/multiplicity/`{ordered}/{unique}/{readOnly}` modifiers, template-parameter box `x_template`, and structured association attachments `x_association_class`/`x_nary`/`x_genset` with reference pickers; end-label editing stays in the Inspector), **UML activity** (`uml.activity@1`/`@2` — lane editor over view frames: add/rename/resize X/Y/W/H/fit-to-members, assign/unassign with the one-lane policy, maintaining `x_partition`), **UML sequence** (`uml.sequence@1`/`@2` — the prototype's declaration-order lifeline strip and message table ported: reorder by declaration-span move, label, `x_return` true-or-absent, add existing/new participant, add message; plus `x_message` annotations and a one-level `x_fragment` editor), **BPMN** (`bpmn.*@1` — `x_event` type/position/interrupting/on, `x_gateway` type, `x_interrupt` on flows), and **Patent** (view kind `patent-figure` — numeral editor with the DDN-VP06 conflict warning adjacent, `ref:` anchor list/insert helper, and a previewed renumber pass). Dispatch gained a `viewKinds` match because `patent.legal@1` attaches through the view kind, never the projection profile. Data-projection sheets (chart, matrix, decision, timeline, fishbone, panels) are phase 6b.
>
> Implementation status (2026-10 redesign, phase 6b): the six data-projection sheets are registered, completing the Type sheet set — **Matrix** (`matrix.*@1` — batch cell grid over the projection plan's rows/columns; a keypad stages RACI/CRUD letters per cell, the staged batch commits as ONE `authoring.setMatrixCells` transaction with a chip preview, arrows/Enter/Esc keyboard support; cells are editable only when the value binding is an `x_*` extension property), **Chart** (`chart.*@1` — binding form writing the view-scope `projection { }` group through the new `authoring.setProjectionProperty`: mark (from the capability `marks` set), x/y/size/unit/aggregate/missing, with data-aware field pickers offering only keys present on the bound records (y/size: keys numeric on every record that declares them); plus the shared-model record table — typed cells via `authoring.setRecordValue`, numeric strings never coerced — and add/delete record flows), **Timeline** (`timeline.*@1` — date controls per item writing a merged two-key `x_record` so a start edit never passes through an intermediate end < start state, ISO real-calendar grammar pre-checked; dependency link/unlink editor — unlink removes the view's `projection.dependencies` ref and keeps the shared relation), **Decision** (`decision.rules@1` — the prototype's typed predicate cells ported verbatim: enum multi-select for `in`, interval min/max + closure checkboxes for numbers, true/false for booleans, `null`/`missing` operators only when the domain declares them; typed outcome cells, `hit_policy`/`coverage` view-scope pickers, records-order ↑/↓ (semantic for first-match policies), the analysis summary (status/atoms/uncovered/overlaps/shadowed/unreachable) and the read-only fixture evaluator), **Fishbone** (`fishbone.*@1` — effect label editor, rib tree with occurrence counts, add cause/category, attach existing cause as a relation-only second occurrence, remove rib keeping the definition), and **Panels** (`panels.*@1`/`panels.composed@1`/canvas profiles — a grid mirror plus per-panel cards: title, row/column/rowspan/colspan, item assignment with move-to-panel picker, add item, delete, and the child-view slot binder with rebind and open-child-view; fixed-grid canvas profiles lock their required blocks' controls, `panelGridCheck` pre-checks DDN-PJ020/021/QP001 and the commit-time build stays the authority). Dispatch now also matches kind-only sheets (no profile list) so every data-bound projection kind resolves a body — the phase-2 "generated from data" palette hint names it. New authoring channels: `setProjectionProperty` (projection-group property writes with resolved-uid → alias-aware `$ref` normalization) and `setViewList` (view-body select/exclude/data list rewrites, used by the chart/decision delete flows to drop the auto-added select ref). Unlike the prototype, decision analysis failures (DDN-QD004/005/008) reject the commit with the coded error instead of committing as a draft.

## Design screens
The supplied design prototype covers the graph inspector, field connection, pin/layout settings, source/changes, projected matrix, chart binding, shared-change review and save/export concepts. Mock-only screens are marked as review designs. The prototype's working actions and exclusions are documented separately; it is not the released full editor.
