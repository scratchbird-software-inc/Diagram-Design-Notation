# DDN runtime and commands

This GPL-2.0-or-later package owns the existing local runtime and command service. It implements the adopted utility ABI; the private source publication boundary does not add a second command API or a service transaction protocol.

`createRuntime` retains one committed immutable model snapshot and an independently revisioned editable source buffer. Invalid source stays available with diagnostics while the previous valid snapshot remains visible. Source text and supplied UTF-8 bytes must agree, allowing a leading BOM retained only in the bytes. Input and returned byte buffers are copied. Provider updates copy source, schema and data payloads before asynchronous work, then publish one source/model/data frontier after validation. Cancellation, obsolete work and failed verification leave committed state unchanged.

`createCommandService` captures an intent before asynchronous profile preparation. Generated creation identities and semantic changes are deterministic for the same base revision and intent. Source patches retain declared file ownership, and qualified local/URL references use the language's canonical namespaces. Provisional local domains reuse NFC-equivalent identities; explicit foreign domain references must resolve rather than manufacture a local or foreign declaration.

Preparation computes sorted write sets and semantic deltas. It currently runs workarea-wide semantic verification, so its read set conservatively includes every existing record. Typed reference dependencies drive dependent removal and protected-scope checks. Exact source/context, revision and registry checks cover file-level and absent-record inputs. This packet does not claim a minimal per-rule read set or fine-grained verifier cache execution. Comment-only source changes retain the model revision and semantic fingerprint while advancing source evidence.

Commit rechecks the captured source context, complete source representation, revision, installed rules, current principal and authorization after candidate decoding and verification. Lifecycle commands recheck transition eligibility and grants. Successful publication has an explicit internal commit marker; a returned previous snapshot cannot imply success. Pending-command and history bookkeeping completes before revision notifications. Concurrent commits or history operations on one service fail with a conflict and can be prepared again; they do not overwrite each other.

Undo/redo runs through current preparation, authority and validation against the current source frontier. Lifecycle changes stay outside inverse history. Grouped settings retain one source-patch history entry; history stores patches rather than full snapshots for each edit. The configurable default limits remain 200 commands and 32 MiB, and exhaustion emits a `history.checkpoint` diagnostic without discarding current source. Failed transactions leave history unchanged.

Maintained regressions are in `project/tests/CORE02/runtime*.test.mjs` and `project/tests/ddn/runtime`. The CORE02 vectors include paused asynchronous verification/decode races, source-byte ownership, deterministic preparation, multi-file edits, invalid-buffer retention, provisional domains, source-only revisions, cancellation, and undo/redo. Durable multi-user ordering, authoritative service grants, visual rendering and later qualification gates remain outside this local runtime packet.
