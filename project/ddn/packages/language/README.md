# DDN language implementation

`decodeSources(sourceSet, {previous?, cancel?, budget?})` reads the new `ddn-next-1` indentation dialect. It does not read the proof-of-concept dialect. Its normalized bundle follows the adopted property codex; omitted defaults remain omitted. Lexical property shapes share the verifier's compiled metadata through `@ddn/profiles`.

The result contains the normalized bundle, diagnostics, dependency coverage, physical source documents, declaration/property spans, reference spans, and `syntaxValid`. Missing includes and unresolved references produce partial coverage. Malformed syntax does not authorize replacing a runtime's last valid model. The caller retains the original `SourceSet`; decoding never rewrites source.

Included files retain independent name scopes and source ownership. Only the explicit include closure is parsed. CSS and other supplied resources remain host data. File-qualified references resolve after the include graph and template instances are available. Quotes protect punctuation; tables distinguish null positions from explicitly quoted empty text. Draft and note blocks retain their raw text semantics.

The native short forms are ERD, mindmap, and bar. The mindmap recipe creates an unnamed root carrying the view title, with `object` topics and `assoc` branches. Appearance body mode stays omitted until explicitly set; the standard title-only default remains authoritative. Unambiguous inline `position`, `size`, `body`, and `columns` settings belong to the implicit appearance. Shared `font`, `title`, and column visibility settings belong to the definition unless an explicit `use` occurrence owns the override.

Source edits use revision-checked `SourcePatch` records. `patchProperty`, `renameDeclaration`, `deleteDeclaration`, `appendDeclaration`, `replaceDraftBody`, and `replaceDataBody` preserve unrelated source text. Table edits select compact rows when they represent the data exactly and typed properties otherwise. Normalized identities of implicit appearances follow their view and target, so staged and direct transactions agree. Generated recipe members must be edited through their owning table/recipe. An implicit occurrence shares its declaration span; occurrence-only removal needs a separate materialization operation.

Patch offsets are finite safe integers in UTF-16 code units. All selected file identities, revisions, writable flags and nonoverlapping ranges are checked before any changed file is returned. Canonical file identities address the original selected file spelling; aliases selecting the same file twice are rejected. No-op patches retain the original file and byte references. An actual edit regenerates supplied UTF-8 bytes, retaining a separately stored BOM when the host omitted it from text. Caller input is not modified. Targeted replacements retain absence of the final newline, and insertions reuse authored sibling indentation.

Structural indentation uses spaces, including after a leading BOM. Tabs and lone carriage returns are rejected in structural/property lines; literal note, draft and data content retain their permitted characters. Quoted row cells cannot span physical lines. Multiline property edits use only registered, unambiguous text-body shapes; values such as multiline strings inside generic JSON/list unions are rejected before producing patches because the admitted notation cannot represent them unambiguously. This does not introduce a new quoting or item syntax.

Templates bind typed arguments, apply settings below explicit instance values, and expand child definitions, views, appearances, and notes using deterministic instance identities and prefixed names. Unknown arguments, type mismatches, required missing values, recursive expansion, and collisions are diagnostics. The reconciled template fragment has no named data collection, and the implementation does not invent one. Document sections and relationship endpoints admit only their registered properties; broader prose does not widen their schemas.

Maintained language tests are under `project/tests/ddn/language` and `project/tests/CORE01/language*.test.mjs`. They cover the adopted consolidated examples, parser errors, include cycles, reference ownership, templates, recipes, table precision, and source-preserving designer transactions. Runtime budgets and cooperative scheduling are coordinated by `@ddn/execution`; parsing within a single synchronous decode remains a bounded integration concern rather than a claimed scheduling benchmark.
