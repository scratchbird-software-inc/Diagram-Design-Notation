# Notation coverage and completion boundaries

The [language reference](09-language-reference.md) provides generic forms for retained profiles, element roles, relation roles and registered property trees. The machine-readable route inventory (historical specification citation) enumerates the source route for each existing entry; it preserves catalogue restrictions and records which property owners are authored, derived or session state.

| Inventory | Entries with an explicit notation route |
| --- | ---: |
| Core information types | 55 |
| Native relation patterns | 94 |
| Retained profiles | 151 |
| Retained element roles | 375 |
| Retained relation roles | 185 |
| Baseline shared property records | 262 |
| Catalogue entries with their existing inclusion boundaries | 308 |

Structural types use dedicated forms such as workarea, view, use, document, data and notes. Other registered types use element plus a typed with block. Relationships use connect or, where registered, ordered endpoint declarations. Generic notation never makes an inapplicable property legal or converts an excluded capability into an included one.

The property routes are access to the existing baseline catalogue, not a fully reconciled reference codex. In particular, the old draft/review enum is superseded by the owner's four user-set states, document output properties must be integrated with views, and local table/data/notes rules need normalized schema updates. Read-only results and session state are not made settable simply because their shapes can be described.

[Consolidated examples](examples/consolidated/README.md) cover the authoring patterns. The audit report (historical specification citation) records only the checks actually performed: route counts/uniqueness, required files, selected property/profile anchors, structural indentation, reference fixture expectations, link existence and selected quote/table cases. It does not report a parser, renderer or semantic verification pass.

The inferred notation decisions are complete for this draft's declaration, reference, property, text, table, data, output and lifecycle forms. Remaining work is expansion/reconciliation of semantic property/default records, the machine schemas, icon artwork and software implementation. No backward-compatibility or migration syntax is required.

Historical evidence/source snapshots cited in this chapter are excluded from the standalone distribution. Current behavior and qualification are documented in [the public project](https://github.com/scratchbird-software-inc/Diagram-Design-Notation).
