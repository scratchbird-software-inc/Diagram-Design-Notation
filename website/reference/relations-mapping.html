Reference — Mapping & representation relations

Mapping relations say this stands for that: a table represents a business entity, a field binds to a domain, a copy is a copy of. They are the glue between the meaning layer and the building layers — the lines that let one model serve an ER diagram and a concept diagram without drifting apart.

This page lists every Mapping relation in DDN — 20 of them. Relations are declared inside a data block: relation id "label" @from -> @to { kind: …; }. Every example on this page passes the tool’s own check and render steps.

Mapping relations end in an open arrow pointing at the thing being represented or bound. No cardinality marks. Labels name the mapping when the verb alone isn’t enough.

represents (represents)

What it means. Data representation to business concept. It ends with a open arrowhead — read it in the arrow direction: “From → To”.

Example — paste it into the tool’s source drawer and Apply
ddn "0.5";
module "wiki.ref.relations";

// represents (represents) between two elements.
data demo {
    object from_side "From" { kind: object; }
    object to_side "To" { kind: object; }
    relation shows "represents" @from_side -> @to_side {
        kind: represents;
    }
}
