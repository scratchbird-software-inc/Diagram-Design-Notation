Profile verification

  • Every visible ref/assoc edge declares both endpoint marks: one, zeroone, many or zeromany. Unknown marks are rejected.
  • Native progressive entity editing remains available; a simple named box does not require field detail.
  • The four marks do not carry Chen weak/identifying semantics; explicit numerical bounds retain their separate properties.

Profile defaults

Explicit file settings override eligible CSS, then these profile defaults and the common standard apply. Unspecified semantic facts remain unspecified.

{
  "projection.kind": "graph",
  "projection.profile": "erd.crowfoot@1",
  "entity.initial_body": "title-only"
}

Design operations

  • Use native entity drafting commands; connect ref/assoc and choose cardinality independently at each end.
Bounded analysis

Structural verification and display only; no execution or implied process engine.

Outside this profile

  • min/max beyond the four marks (use source_min/target_max properties)
  • identifying-relationship semantics (see chen.binary@2)
  • schema generation without an allowlist (see RT-020)
