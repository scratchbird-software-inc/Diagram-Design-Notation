Reference — every element kind and relation

This is the complete shelf catalogue of DDN. Every element kind (the boxes and symbols you can place — 375 of them) and every relation (the lines between them — 185 of them) gets its symbol, a plain-language meaning, the extra information it accepts, and a small example you can paste into the tool as-is. Every example in this reference passes the tool’s own check and render steps.

Why so many kinds? Because a diagram that says exactly what a thing is — a queue, not a box labelled "queue-ish" — never needs a footnote. You don’t need to know them all. Skim the family that matches your job, steal an example, and come back when you meet something new.

How to read a kind page

Each kind entry shows four things: what it looks like (the drawn symbol), what it represents (the idea, not the picture), where it shows up (the diagram types that use it), and what you can add (optional properties — labels, datatypes, keys, notes and so on). The examples are minimal on purpose: they pin nothing down, so DDN picks the layout and you see the kind’s own defaults.

Style never changes meaning. A table drawn hand-drawn, neo, or plain is still a table — looks come from styles, meaning comes from the kind.

Looking the other way

If you know the diagram you want and need its symbols, start from the gallery instead — every installed profile rendered — or the wiki’s diagram type pages.
