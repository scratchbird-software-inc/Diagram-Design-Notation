Reference — Lineage & derivation relations

Lineage relations say where this came from: derives from, aggregates, joins, filters, masks. They answer the auditor’s favourite question — “says who?” — by tracing a number back to its sources. Lineage reads backwards along the arrows: start at the report, walk to the raw data.

This page lists every Lineage relation in DDN — 11 of them. Relations are declared inside a data block: relation id "label" @from -> @to { kind: …; }. Every example on this page passes the tool’s own check and render steps.

Lineage relations end in a filled arrow pointing the way derivation flows (source → derived). No cardinality marks. Labels name the transformation when it isn’t obvious (“daily rollup”, “PII masked”).

derives into (derives)

What it means. Upstream data to derived data; opposite to the spelling of prov:wasDerivedFrom. It ends with a filled arrowhead — read it in the arrow direction: “From → To”.

Example — paste it into the tool’s source drawer and Apply
ddn "0.5";
module "wiki.ref.relations";

// derives into (derives) between two elements.
data demo {
    object from_side "From" { kind: object; }
    object to_side "To" { kind: object; }
    relation shows "derives into" @from_side -> @to_side {
        kind: derives;
    }
}
