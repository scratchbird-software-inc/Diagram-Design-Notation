Reference — Dependency & reference relations

Dependency relations say needs: this report needs that dataset, this service calls that API, this field uses that domain. A dependency does not say data moves — that’s what flow relations are for. Dependency lines are dashed with an open arrow, so a reader can tell “talks to” from “sends to” at a glance.

This page lists every Dependency relation in DDN — 39 of them. Relations are declared inside a data block: relation id "label" @from -> @to { kind: …; }. Every example on this page passes the tool’s own check and render steps.

Dependency relations end in an open arrow — direction of need, read the verb. No cardinality marks. Labels name the nature of the need (“reads schema”, “onboarding queries”).

depends on (depends)

What it means. Dependent definition to the definition it requires. It ends with a open arrowhead — read it in the arrow direction: “From → To”.

Example — paste it into the tool’s source drawer and Apply
ddn "0.5";
module "wiki.ref.relations";

// depends on (depends) between two elements.
data demo {
    object from_side "From" { kind: object; }
    object to_side "To" { kind: object; }
    relation shows "depends on" @from_side -> @to_side {
        kind: depends;
    }
}
