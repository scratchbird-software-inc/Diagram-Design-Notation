Architecture

One model and shared rules.

Small modules separate semantic work from rendering, editing, IO and optional services.

ModulesResponsibility
typesCore, scene and browser API contracts.
model, languageQualified identities, indentation parsing, typed records and source patches.
profiles, defaultsCodex, profile rules and file > CSS > standard resolution.
executionFingerprints, budgets, cancellation and optional worker execution.
runtimeImmutable revisions, data providers, commands, lifecycle protection and history.
presentation, viewerProfile scenes, tables, safe Markdown, navigation, inspection and capture.
designerEditing controls using the shared viewer and command service.
verifier, standaloneStaged verification and local browser application shells.

Versioned identity and updates

Definitions carry stable identity separate from the displayed label. Files retain their identity when included in a main workarea. Commands and data revisions check their base state so a stale operation cannot quietly overwrite newer work.

Boundary with Weaver

The DDN foundation is a standalone single-user client system. Commercial coordination, multi-user collaboration, meetings, media and server paging are Weaver responsibilities. None is required to open or edit a local DDN diagram.

Scope and qualification

The complete edition implements the adopted bounded profiles. Full standards execution and external certification are not implied. Browser, accessibility, performance and release qualification remain separate from the presence of a profile in the registry.
