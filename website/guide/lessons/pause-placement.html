Paused placement — retaining the current scene

Auto-placement switched off for a view: the engine retains the current positions and refuses to re-derive them.

ddn@1New DDN source
Open viewerOpen designerRun verifierDownload DDN

Why use it?

A reviewed layout is a reviewed artefact — pausing freezes what was approved while the model keeps evolving underneath.

When it helps

Baselined publication views, and any diagram whose composition was agreed in a review.

How to read it

  • The scene renders retained positions; new elements still need a declared seed position.
  • The info diagnostic (auto-placement paused) is the engine stating the contract, not an error.

What you need

  • The model
  • The retained positions
  • Seed positions for anything new

Things to check

  • Do not pause early — pausing freezes today's accidents along with today's decisions.
  • A new element with no seed position under paused placement is a declaration gap you must fill.
Scope of this diagram

Retention of declared/current positions with auto_place off; it preserves positions, not model semantics.

Work with the converted example

  1. Open the viewer and select paused. Inspect the rendered view and its source.
  2. Open the designer. Keep the selected profile and inspect its legal palette and property controls.
  3. Change one displayed title or an appropriate data value. Check the live update in the resulting diagram.
  4. Run the verifier and review its diagnostics before moving complete content into review.
  5. Download your edited DDN source to retain the change.

The example uses the indentation-based ddn-next-1 dialect. The language guide explains reusable definitions, dotted data rows and explicit property blocks.
