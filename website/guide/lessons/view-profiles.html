View kinds and strictness — declaring what a view is

field-guide/sources/view-profiles.ddn # flow_strict

technique

What this diagram shows

kind: names what sort of diagram a view is (flowchart, c4-context, uml-class, patent-figure, …); strictness: decides whether straying outside that vocabulary is an info note or a check failure.

Why use it?

A declared kind turns "this looks wrong" into a coded diagnostic: permissive mode reports each out-of-vocabulary element as DDN-VP03, strict mode fails the check with DDN-VP04 naming the fix.

When is it useful?

Any view that claims to follow a notation: declare the kind, then choose strict for regulated deliverables and permissive while drafting.

How to read this example

  1. The strict variant is a closed flowchart: start, end and labelled decision branches, all inside the flowchart vocabulary.
  2. The permissive variant adds a note — outside the vocabulary — and renders normally with one DDN-VP03 info diagnostic.
  3. kind pins defaults only: an explicit style, layout or projection declaration still wins over the kind-derived default.
  4. Independent of strictness, a kind's attached profile keeps its own contracts — the flowchart profile itself rejects non-flow participants (DDN-PF007), which is why the lenient guest example uses the graph-based patent-figure kind.

Information to gather first

  • The diagram's claimed notation
  • The tolerance for vocabulary strays (draft vs deliverable)

How to author this view

  1. Open field-guide/sources/view-profiles.ddn and locate view flow_strict. This selects existing data; it is not a stored SVG.
  2. Inspect the flow.documented@2 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.

Boundaries and common mistakes

Registered kinds are ddn-native, flowchart, the c4 and uml families, chart-bar/chart-line, ladder and patent-figure; an unknown kind is DDN-VP01, strictness without a kind is DDN-VP02. Themes colorblind_safe and mono_print re-skin paint only — geometry, layout and text are identical across themes; an unknown theme is DDN-VP08.

  • Do not declare a kind to change the picture — kinds never alter routing or layout; they set defaults and a lint axis.
  • Do not confuse strictness with validation: strict governs vocabulary membership only and never relaxes profile or geometry checks.
