What this diagram shows

ITU SDL: the system as blocks and channels, and inside a process the state machine with input, task, output and decision symbols.

Why use it?

SDL pairs the structural channels with the behavioural states in one standard — the two views check each other.

When is it useful?

Telecom and reactive-system documentation where signal protocols meet state behaviour.

How to read this example

  1. In the system view, blocks exchange signals over named channels.
  2. In the process variant, read top-down: start, input, task/decision, output, next state.

Information to gather first

  • The blocks and channels
  • The signal sets
  • The process states and transitions

Boundaries and common mistakes

Declared SDL with structural validation; no code generation or exhaustive simulation is claimed.

  • Do not send a signal over a channel that does not carry it.
  • Every decision branch needs a continuation; an unhandled input is a stuck process.
