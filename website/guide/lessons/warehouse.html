What this diagram shows

A star schema: one fact table surrounded by dimensions, with grain declared.

Why use it?

The star makes analytical queries legible — and the grain declaration prevents the classic double-count.

When is it useful?

Designing marts, cubes or any reporting model.

How to read this example

  1. The fact table is events or measurements; dimensions answer who/what/where/when.
  2. Every fact row means exactly one thing — that is the grain.

Information to gather first

  • The grain
  • The measures
  • The dimensions and their levels

How to author this view

  1. Open website/examples/use-cases/15-warehouse.ddn and locate view diagram. This selects existing data; it is not a stored SVG.
  2. Inspect the ddn@1 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
