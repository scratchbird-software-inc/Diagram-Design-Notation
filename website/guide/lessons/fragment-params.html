Parameterized fragments — one template, many instances

field-guide/sources/fragment-params.ddn # main

technique

What this diagram shows

A fragment declares 1-8 parameters (fragment staged(name, table) {…}) and each use: binds them positionally, stamping out declarations as if handwritten; definitions may also apply other definitions (nested use:).

Why use it?

A pipeline of identical stages is one template, not five copies to keep in sync: rename the stage kind or add a field once and every instance follows — with identities exactly as if you had typed each stage out.

When is it useful?

Repeated sub-models (stages, tiers, mirrored pairs), template libraries shared across files, any place a copy-paste block keeps drifting.

How to read this example

  1. staged(name, table) stamps a service card and its flow to the audit trail; pipeline(first, second) applies it twice (nested use:) and chains the stages — ingest and reconcile render like any handwritten card.
  2. Substitution is token-level: a declaration id, a whole @reference, a whole property value, or ${name} inside a string. name_out would be one token — identifiers never interpolate inside, so kebab rules always hold.
  3. The expansion is IR-identical to the handwritten model: equivalence is gated by fixtures, and inspectors treat expanded content as derived/read-only — edit the use: site (local override) or the fragment (all instances).
  4. Cycles between definitions are DDN-FG04 and nesting past 8 levels is DDN-FG05; arity, unknown ${…}, and bad identifier args are DDN-FG01/FG02/FG03.

Information to gather first

  • The repeated shape and what varies per instance
  • Parameter names and their positions (id, reference, value, string)
  • The maximum reuse depth (cap 8)

Boundaries and common mistakes

Arguments bind positionally (DDN-FG01); an argument that cannot serve its position is DDN-FG03. Below ddn "0.6" parameters/arguments are DDN-V04 and nested use: stays DDN-E017.

  • Do not expect name_out-style identifier interpolation — put the varying part in a whole id token or a ${…} string.
  • Do not edit an expanded instance hoping to change the template — expansions are derived; edit the fragment or override at the use: site.
