What this diagram shows

A wide-column layout: rows keyed for the queries they must serve, column families grouped by access pattern.

Why use it?

In wide-column stores the query writes the schema — documenting which access pattern owns which family prevents expensive mistakes.

When is it useful?

Designing or reviewing Cassandra/Bigtable-style tables.

How to read this example

  1. Read from the partition key outward: what is looked up together lives together.
  2. Column families are access patterns, not topics.

Information to gather first

  • The queries the system must answer
  • Partition and clustering choices
  • Families per pattern

Boundaries and common mistakes

Design documentation; no distribution or compaction behaviour is modeled.

  • Do not model wide-column tables relationally and expect the queries to work.
  • Do not create a family nobody reads.
