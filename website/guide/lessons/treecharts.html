What this diagram shows

Hierarchies as nested area: sunbursts, tidy/radial trees, circle packing and packed bubbles from one hierarchy.

Why use it?

Nested magnitude reads differently in each form — the pack lets the data pick the right one.

When is it useful?

Org size, budget trees, file storage, taxonomy size.

How to read this example

  1. Area is value, nesting is structure.
  2. Read outward (sunburst) or along branches (trees) — never compare area across different forms directly.

Information to gather first

  • The hierarchy
  • The value per node
  • The depth you actually have

How to author this view

  1. Open website/examples/basics/63-tree-charts.ddn and locate view sunburst. This selects existing data; it is not a stored SVG.
  2. Inspect the chart.sunburst@1 profile and chart projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
Actual view declaration
view sunburst "Sales hierarchy / sunburst" {
    data: [@sales];
    projection { kind:chart; profile:"chart.sunburst@1"; records:[@sales.n1, @sales.n2, @sales.n3, @sales.n4, @sales.s1, @sales.s2, @sales.s3, @sales.s4, @sales.s5]; mark:sunburst; x:"x_record.path"; y:"x_record.sales"; unit:"kEUR"; width:1120px; height:620px; }
    publication { size: content; fit: none; }
}

Boundaries and common mistakes

Declared hierarchy and values; layout is deterministic per form.

  • Do not force deep hierarchies into a sunburst — they become confetti.
  • Do not compare sibling sizes across separate charts.
