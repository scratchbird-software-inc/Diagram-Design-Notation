What this diagram shows

The project as a deliverable tree: each level decomposes its parent into 100% of the work, no more.

Why use it?

Estimation and assignment both start from the same tree — the 100% rule is what keeps scope honest.

When is it useful?

Project initiation, before any schedule network (see the PERT chapter for the dependency view).

How to read this example

  1. Each box is a work package or a grouping; children sum to their parent.
  2. The leaves are what gets estimated and assigned — groupings are never "worked".

Information to gather first

  • The deliverables
  • The decomposition rule (by outcome, not by department)

Boundaries and common mistakes

Declared decomposition; effort and dates belong to the schedule artefacts, not this tree.

  • Do not decompose by org chart — the WBS is deliverables, not headcount.
  • A child that overflows its parent's scope breaks the 100% rule.
