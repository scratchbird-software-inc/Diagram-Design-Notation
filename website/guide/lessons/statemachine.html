What this diagram shows

States, transitions with triggers/guards/effects, plus the full pseudostate vocabulary: initial, choice, junction, history, entry/exit points.

Why use it?

State machines make "what may happen next" enumerable — reviewers can ask about every missing transition.

When is it useful?

Lifecycle-heavy objects: orders, connections, approvals, devices.

How to read this example

  1. Rounded boxes are states; arrows are transitions labelled trigger [guard] / effect.
  2. Filled circles and diamonds are pseudostates — routing, not resting places.

Information to gather first

  • The states
  • The events that drive transitions
  • Guards and effects

Boundaries and common mistakes

Declared machine with well-formedness validation; no code execution or model checking is claimed.

  • Do not leave a state with no path out unless it is final by intent.
  • Do not put work in a pseudostate — effects belong on transitions.
