What this diagram shows

Blocks, their properties (parts, values, references) and the relationships between blocks: composition, generalisation, association.

Why use it?

The BDD is the system's nouns and their structure — every other SysML view hangs off these definitions.

When is it useful?

Systems architecture decomposition, from vehicle-scale down to a single assembly.

How to read this example

  1. Blocks are boxes with compartments; filled-diamond lines are composition (owned parts).
  2. Read multiplicities on part ends — they bound the internal block diagram.

Information to gather first

  • The blocks
  • Their properties
  • The structural relationships

How to author this view

  1. Open website/examples/basics/85-sysml-blocks.ddn and locate view bdd. This selects existing data; it is not a stored SVG.
  2. Inspect the sysml.bdd@2 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.

Boundaries and common mistakes

Declared structure with SysML well-formedness validation; no analysis or simulation is implied.

  • Do not confuse composition (part-of, one owner) with reference (used-by).
  • A part with no multiplicity is an under-specified IBD waiting to happen.
