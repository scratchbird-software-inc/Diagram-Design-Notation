What this diagram shows

One small hierarchy rendered by each native placement algorithm: grid, layered, tree, circular, radial, organic and more.

Why use it?

The algorithm is the argument structure: layered reads as flow, tree as descent, radial as containment — pick deliberately.

When is it useful?

Any new view: choose the placement that matches the question before tuning anything else.

How to read this example

  1. Switch variants: same six elements, same relations — only the placement changes.
  2. Read the layered variant for direction, the radial for orbit distance, the grid for census.

Information to gather first

  • The model
  • The algorithm declaration (and its root/columns/direction where relevant)

How to author this view

  1. Open website/examples/gallery/src/layouts.ddn and locate view layered. This selects existing data; it is not a stored SVG.
  2. Inspect the ddn@1 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
Actual view declaration
view layered "Layouts / layered" {
    data: [@model]; style: @gallery.standard; display: @gallery.readable; publication: @gallery.screen; legend: @gallery.key;
    layout { algorithm: layered; direction: right; }
}

Boundaries and common mistakes

The registry's native and pattern algorithms; custom placement is the pinned-placement technique.

  • Do not hand-tune positions before the algorithm is right — that is fighting the tool.
  • A tree algorithm on a cyclic graph hides the cycles; check the relation kinds first.
