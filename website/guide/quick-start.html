Quick start

Create a diagram in a few lines.

Use spaces to indent, one declaration per line, and leave ordinary settings at their defaults.

Start visually

On the empty designer, choose New document… and name the workarea. Choose Create Standalone View for one view whose workarea follows its size, or Create WorkArea for a surface holding multiple views and documents. Workarea setup has a name field and disabled Settings and Permissions buttons with explanatory hints; these managed features belong to Weaver. Choose Apply to continue. Both paths next show Choose view layout. Choose Dynamic for a surface that follows its contents, or a fixed TV dashboard size: HD, Full HD, 2K, QHD, 4K UHD or 8K UHD. Each tile shows its pixel dimensions and explains its defaults on hover or keyboard focus. Physical pages and PPTX/ODP presentation layouts appear greyed out for Weaver. Choose Continue, then select a diagram-method preview and one of its diagram-type previews. Enter a view name and choose Create view. Use All diagram methods to go back, or search the types within a method. The view inherits the selected type’s defaults and opens the matching element palette, or data and projection controls for charts and tables. To replace an existing document, choose File → New diagram…. New confirms unsaved work, then clears the current source, workarea and undo history; download any work you want to keep first. Use Add element to open the palette, choose a type and click on the canvas. Double-click an element to rename it; Properties opens its inspector. File → Open a sample… provides starter diagrams. Cancelling creation leaves an empty document. Standalone mode is saved in the DDN source; it hides workarea navigation and the commands for adding another view. Adding a view also starts with layout selection. Changing the diagram type of an existing empty view preserves its layout. Dashboard sizes remain fixed as content changes; content scales to fit, and fonts, colours and backgrounds remain customisable.

Adjust the diagram live

Choose sample buttons for textures, fonts, paper, shadows and symbols. Sliders and exact values update the diagram immediately. Close keeps valid changes; Revert changes restores the settings session, and Undo reverses it after closing. Invalid values leave the last valid diagram visible. Font sizes in Appearance are shown in points.

The element palette previews the actual symbols for the selected diagram type and groups available items with tabs on the left. Close a drawer to free canvas space, reopen it from its tab, or use Float and Pop out to move its controls. A pop-out is a separate browser window that can be moved to another monitor. Use Dock to return it. Drag the lower-right grip to resize a floating panel or form. Selected editable elements also show a lower-right resize grip; release to keep the new size, or press Escape during the drag to cancel. Your browser must allow pop-ups for a separate window; otherwise the panel floats within the page.

Place and arrange elements

Drag an element type from the palette onto the view, or click the type then its position. New elements stay where placed until connected, then join the diagram’s automatic layout. Moving an already connected element fixes its position. Choose Reflow to release fixed positions and custom route waypoints in the active view and arrange it using its diagram type and relationships. Undo restores the previous layout.

The corner status dot is amber for Draft, blue for In progress, purple for In review, and green for Accepted. Hover over or keyboard-focus the dot for an explanation. Select the element and choose More → Status to change its status.

Relation labels and legends

Right-click a relation to toggle Label visible, Number instead of text and Include in legend. Each setting updates immediately and affects this appearance only. A hidden label can still appear in the legend. Undo restores each change; saving keeps these settings in the DDN source. Internal mind-map links stay unlabelled and out of the legend.

1. Name the view and its entities

erd Sales
    Customer
    Order
    connect Customer to Order

erd Sales creates a native DDN ERD view. The two indented names create entities. The connection uses the profile’s default relationship. There is no requirement to invent fields or keys before the ideas are ready.

Open the designer and start a document

2. Choose a connection type when you need one

erd Sales
    Customer
    Order
    connect Customer to Order as assoc : places

as selects a relation role; the colon introduces its displayed label. The selected profile determines which relations and endpoint roles are legal.

3. Add fields gradually

erd Sales as field:lt.type:ct.domain:lt.key:ct
    Customer
        Id.int..primary key
        Name.varchar(25)
    Order
    connect Customer to Order

Dots separate cells. Two dots leave an empty cell, and missing trailing cells remain empty. Each physical line is one row; long cell text wraps on screen. A field’s name does not need a datatype until the design is ready for it.

4. Try a different type of view

A mind map

mindmap Launch
    Research
        Interviews
    Delivery
        Release notes

A small chart

bar SalesTotals
    North 120
    South 95

Mind-map nesting creates branches because that recipe defines it. Ordinary indentation in other profiles does not invent relationships.

5. Add only the settings you want to change

erd Sales
    Customer
    with
        look handdrawn
        font serif

File settings override eligible CSS presentation settings. CSS overrides the selected version’s standard defaults. Semantic facts and status are explicit data; they are not supplied by a theme.

6. Review the source and the result

  1. Open an example from the gallery in the viewer and inspect the source.
  2. Open its designer, make a small change and apply it.
  3. Check the diagnostics in the verifier. Draft content may be incomplete; review requires complete, passing content.
  4. Download the edited source and a supported rendered snapshot.
