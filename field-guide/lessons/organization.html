What this diagram shows

Reporting lines as a tree: units and roles, top down, with names and titles in the boxes.

Why use it?

Escalation paths and span-of-control questions are answered by the shape before anyone reads a name.

When is it useful?

Onboarding docs, reorg proposals, RACI context (who the letters are).

How to read this example

  1. Each box is a role or unit; the line above is its manager.
  2. Wide layers are wide spans; deep chains are slow escalations.

Information to gather first

  • The roles
  • The reporting lines

How to author this view

  1. Open website/examples/basics/26-org-chart.ddn and locate view org. This selects existing data; it is not a stored SVG.
  2. Inspect the org.tree@1 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.

Boundaries and common mistakes

Declared hierarchy; HR-system accuracy is documented, not synchronised.

  • Do not draw dotted-line influence as a reporting line — mark it differently or omit it.
  • A box with two managers is a matrix claim; draw it deliberately.
