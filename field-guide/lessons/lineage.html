What this diagram shows

Where each dataset comes from: sources, transformations and the datasets they produce, end to end.

Why use it?

Every number on a report should answer "from where" in one look.

When is it useful?

Auditing data products, debugging a wrong number, or onboarding to a pipeline.

How to read this example

  1. Read right-to-left from the report: each arrow is a derivation step you can inspect.
  2. A dataset with no recorded source is an assumption, not a fact.

Information to gather first

  • The sources
  • The transformation steps
  • The produced datasets

How to author this view

  1. Open website/examples/use-cases/13-lineage.ddn and locate view diagram. This selects existing data; it is not a stored SVG.
  2. Inspect the ddn@1 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.

Boundaries and common mistakes

Declared lineage; no data actually flows when you read this.

  • Do not skip the boring intermediate datasets — they are where errors hide.
  • Do not draw lineage at a granularity you cannot actually inspect.
