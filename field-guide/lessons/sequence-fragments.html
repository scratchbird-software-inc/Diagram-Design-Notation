What this diagram shows

A full UML sequence diagram: lifelines, messages, combined fragments (alt/opt/loop), gates and time constraints.

Why use it?

Sequence diagrams are where protocol assumptions get written down and found out.

When is it useful?

Specifying or reviewing message order between components.

How to read this example

  1. Vertical position is time; fragments bracket the conditional parts.
  2. A guard you cannot state in words does not belong on the diagram.

Information to gather first

  • The lifelines
  • The messages in order
  • The fragments and their guards

How to author this view

  1. Open website/examples/basics/76-uml-sequence-complete.ddn and locate view fragments. This selects existing data; it is not a stored SVG.
  2. Inspect the uml.sequence@2 profile and sequence projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
