technique

What this diagram shows

A view with diff: [@v1, @v2] renders the union of both views’ visible models with per-member states: added, removed, changed and unchanged.

Why use it?

Reviewing a change means seeing it, not reconstructing it from two files: one picture shows what appeared, what vanished and what moved — generated from the model, never hand-drawn.

When is it useful?

Migration plans, review packets, change proposals, before/after teaching material — anywhere two revisions of a model need one shared reading.

How to read this example

  1. Members match by local source id: before.worker and after.worker are the same element, so it paints changed (amber, dotted, ~) — it gained a retries field; legacy is removed (red, dashed, struck, −); ingest is added (green, solid, +); store is unchanged and gets no overlay.
  2. Relations carry their own states: r1 is removed, r3 is added, r2 is unchanged — a relation’s state reflects its own record, so an endpoint’s change shows on the element, not the edge.
  3. The diff key beside the title names the operands and the three state channels; under neutral or mono_print the colours drop out and the dash, strike and token channels keep the states readable.
  4. The union is laid out fresh — the operands’ geometry is ignored, so a removed element appears where the union places it among its former neighbours.

Information to gather first

  • The two revisions as data blocks or views with matching local ids
  • Which members should correlate (shared local ids)
  • The diff view’s own layout and publication

How to author this view

  1. Open field-guide/sources/diff-views.ddn and locate view main. This selects existing data; it is not a stored SVG.
  2. Inspect the ddn@1 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
Actual view declaration
view main "Before → after" {

Boundaries and common mistakes

diff and data: are mutually exclusive (DDN-DF01); an operand with duplicate local ids is DDN-DF04 (narrow with select/exclude). Below ddn "0.6" any diff is DDN-V04.

  • Do not rely on uid: to correlate revisions — uids are workspace-unique by construction; the shared local source id is the identity claim.
  • Do not diff a view against itself or a diff of a diff (DDN-DF03) — operands are ordinary views.
