What this diagram shows

Classes with typed attributes and operations, association ends with multiplicities, navigability and aggregation.

Why use it?

The class diagram is the shared vocabulary between domain talk and code — multiplicities make the rules checkable.

When is it useful?

Object-oriented design, domain modelling, or any review of "what has what, how many, owned by whom".

How to read this example

  1. Boxes are classifiers; compartments hold attributes and operations.
  2. Read each association end: multiplicity, role name, navigability — each is a separate claim.

Information to gather first

  • The classifiers
  • Their features
  • The associations with end properties

Boundaries and common mistakes

Declared structure with UML semantics validated; no code generation or behavioural check is implied.

  • Do not leave multiplicity off an end "for now" — it is the claim.
  • Do not model a relationship attribute without an association class or a home.
