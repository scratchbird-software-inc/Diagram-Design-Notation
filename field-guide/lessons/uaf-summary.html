What this diagram shows

The Summary & Overview viewpoint: the executive one-pager framing the architecture — purpose, scope, key elements in one pictogram.

Why use it?

Every viewpoint set needs a front page that says what the architecture is for and which views answer which questions.

When is it useful?

First artifact of any UAF description; the review-meeting opener.

How to read this example

  1. The frame is the overview; members are the key architectural elements selected for the summary.
  2. Read it as a map to the other viewpoints, not a replacement for them.

Information to gather first

  • The architecture purpose
  • The selected key elements
  • The framing statement

How to author this view

  1. Open website/examples/basics/89-uaf.ddn and locate view summary. This selects existing data; it is not a stored SVG.
  2. Inspect the uaf.summary@1 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.

Boundaries and common mistakes

Declared summary frame over a declared model; completeness of the selection is a review judgement.

  • Do not crowd the overview — it is a signpost, not the territory.
  • An element in the frame must exist in the model; a decorative box is a lie.
