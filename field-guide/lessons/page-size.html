technique

What this diagram shows

The same semantic model published two ways: an A4 page with explicit minimum text size, and a content-sized screen render.

Why use it?

The publication block is the contract with the reader's medium — the engine warns instead of shipping unreadable text.

When is it useful?

Anything leaving the screen: print packs, PDF reports, ISO-style documentation sets.

How to read this example

  1. The paper variant fits the model to A4 and declares the smallest text allowed; the screen variant sizes to content.
  2. Overflow is a diagnostic, not a silent crop — read the warnings before exporting.

Information to gather first

  • The model
  • The publication declaration (size, fit, orientation, minimum text)

Boundaries and common mistakes

Declared publication rules with overflow/minimum-text diagnostics; print-driver behaviour is outside the model.

  • Do not raise the scale by shrinking text below the declared minimum — split the view instead.
  • A fit: none choice means you own the extents; check the page in the export, not the preview.
