Text fit — wrap, grow, shrink and honest overflow

field-guide/sources/text-fit.ddn # fitted

technique

What this diagram shows

How boxes adapt to their text: wrap fixes the width and grows downward, grow expands both axes to declared bounds, and shrink steps the font down to a floor.

Why use it?

Hand-tuning box sizes against text that keeps changing is the chore text_fit removes — with bounds and diagnostics so adaptation stays honest instead of silently clipping.

When is it useful?

Long labels, generated text, multilingual content — anywhere text length is not under the author's full control.

How to read this example

  1. The renderer measures, resizes and re-lays-out in at most two passes; whatever still overflows after that is a residual overflow and is reported.
  2. Residual overflow fires DDN-LW07 (wrap/grow) or DDN-LW08 (shrink at its floor) at render time, naming the element, the overflow and the remedy — check stays clean because it never measures.
  3. Under the default layout { quality: error } a residual overflow refuses the render; the variant declares quality: warn, so it renders with the text clipped at the box edge and a visible ellipsis — never invisible text.
  4. size: content artboards grow with the post-fit bounds, so wrap/grow results are always fully visible — and --content-size forces that for one render without editing the source.

Information to gather first

  • The text and how much it may vary
  • The bounds (max_width, max_height, min_font)
  • The quality policy for overflow

Boundaries and common mistakes

Bounds are 40–4000 px and min_font 6–64 px (never above the base font); violations are DDN-TF02/TF03. Text fit changes geometry only — model fingerprints, endpoints and relation identities are unchanged.

  • Do not set max_height without reading DDN-LW07 as a design signal — split the content or raise the bound; clipping is a last resort, not a layout style.
  • Do not rely on estimated metrics for filings: font_pin records the measurement environment so the same source renders byte-identically anywhere (pin files load through the CLI and the host API).
