What this diagram shows

A series on a real calendar axis: dates are data, spacing is honest.

Why use it?

Equal spacing for unequal time gaps is the most common chart lie; the calendar axis removes it.

When is it useful?

Anything timestamped: metrics, events, activity.

How to read this example

  1. Gaps on the axis are gaps in time, not missing pixels.
  2. Read the timezone note before comparing days.

Information to gather first

  • The timestamps
  • The values
  • The timezone of the records

How to author this view

  1. Open website/examples/projections/views.ddn and locate view time_series. This selects existing data; it is not a stored SVG.
  2. Inspect the chart.basic@1 profile and chart projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
Actual view declaration
view time_series "18 / UTC monthly observations" {
    data: [@m.facts];
    format: @f.shared.common;
    projection { kind:chart;profile:"chart.basic@1";records:[@m.facts.m1, @m.facts.m2, @m.facts.m3, @m.facts.m4, @m.facts.m5, @m.facts.m6];mark:line;x:"x_record.date";x_type:date;y:"x_record.value";unit:"CAD"; }

Boundaries and common mistakes

Declared timestamps and bounded marks; no forecasting.

  • Do not resample silently — the axis shows what was recorded.
  • Do not compare series on different time axes.
