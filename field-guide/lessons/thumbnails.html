What this diagram shows

A view that links to another view, and an embedded view that keeps its own composition inside the host diagram.

Why use it?

Detail-on-demand without leaving the page: the overview stays readable while the detail is one declared hop away.

When is it useful?

Layered documentation: estate overviews with per-area details, poster diagrams with magnified insets.

How to read this example

  1. Linked elements open their target view; the inline variant draws the embedded view's own layout inside the host.
  2. The embedded view keeps its composition — moving the host does not rearrange it.

Information to gather first

  • The host view
  • The linked/embedded target views
  • The declared link between them

How to author this view

  1. Open website/examples/basics/08-subdiagrams.ddn and locate view overview. This selects existing data; it is not a stored SVG.
  2. Inspect the ddn@1 profile and graph projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
Actual view declaration
view overview "A view can link to another view" {
    data: [@model]; format: @shared.styles.technical;
    select: [@model.service];
    subdiagram storage "Storage details" { view: @detail; mode: reference; at: [480px,20px]; size: [310px,105px]; }
}

Boundaries and common mistakes

Declared links and embedding with composition validation; no interactive navigation is shipped in the static SVG.

  • Do not nest inline views more than the composition rules allow — one level deep, by rule.
  • A link target that does not exist fails validation, not silently.
