What this diagram shows

Grid-based charts: heatmaps, calendar maps, parallel coordinates and word clouds from declared records.

Why use it?

Patterns across many cells, days or dimensions need a grid, not another line.

When is it useful?

Activity over days, many-metric comparison, term frequency.

How to read this example

  1. Cells are records; colour encodes the declared measure.
  2. Parallel coordinates read as profiles per record, not as trends.

Information to gather first

  • The axes or dimensions
  • The measure per cell/line
  • The scale

How to author this view

  1. Open website/examples/basics/64-grid-charts.ddn and locate view heatmap. This selects existing data; it is not a stored SVG.
  2. Inspect the chart.heatmap@1 profile and chart projection. Read the bindings before changing any value.
  3. Use the source-file picker or select a diagram element to find its declaration. Edit labels or values deliberately; keep identifiers stable unless all references are updated.
  4. Apply the source, inspect diagnostics, and compare the expected result. Export the SVG only after a successful render.
Actual view declaration
view heatmap "Requests by hour and endpoint / heatmap" {
    data: [@cells];
    projection { kind:chart; profile:"chart.heatmap@1"; records:[@cells.h1, @cells.h2, @cells.h3, @cells.h4, @cells.h5, @cells.h6, @cells.h7, @cells.h8, @cells.h9]; mark:heatmap; x:"x_record.hour"; y:"x_record.n"; series:"x_record.endpoint"; unit:"req"; width:1120px; height:620px; }
    publication { size: content; fit: none; }
}

Boundaries and common mistakes

Declared records; no clustering or correlation is computed.

  • Do not read a word cloud as precise frequency — it is emphasis.
  • Do not compare cell colours across differently scaled maps.
