Patent and legal figures — numerals, refs and mono print

field-guide/sources/patent-figure.ddn # fig1

technique

What this diagram shows

kind: patent-figure attaches the patent.legal@1 conventions: a boxed reference numeral under each element header, ref: anchors in prose that render as the target's numeral, and black-and-white page chrome with FIG. numbering.

Why use it?

Legal figures live by their numerals: the specification text references "valve 106", and a numeral that drifts from its element invalidates the page. Anchors computed at render time cannot drift.

When is it useful?

Patent drawings, legal exhibits and any filing that must survive black-and-white reproduction with numbered parts.

How to read this example

  1. Each element declares numeral: and wears it in a boxed field row; duplicates in one view fail DDN-VP06, out-of-range values DDN-VP05.
  2. The note's ref:actuate renders as 106 — renumber the element and every anchor follows automatically.
  3. The portrait page carries the header date, a single border and the FIG. $figure footer; the same model renders content-sized in the variant.
  4. A decision branch without a label is warned (DDN-VP07) under this profile — examiners require every branch labelled.

Information to gather first

  • The figure's elements and their numerals
  • The narration prose that references them
  • The page size and minimum text the filing office expects

Actual view declaration
view fig1 "FIG. 1 — shutoff control method" {
  data: [@method];
  kind: patent-figure;
  // A tall, narrow flow fits a portrait page without shrinking text below
  // the declared minimum — direction is a readability choice here.
  layout { direction: down; }
  publication {
    size: a4; orientation: portrait; margin: 10mm; minimum_text: 7pt;
    header { right { text: "$date"; size: 8pt; } }
    footer { center { text: "FIG. $figure"; size: 10pt; font: serif; } right { text: "Page $page"; size: 8pt; } }
    border { style: single; weight: 1pt; inset: 6mm; }
  }
}

Boundaries and common mistakes

Drawing conventions only: not legal advice, not a patent-office compliance certification, and claim text is not validated. Anchors render as text only — no hyperlink is emitted.

  • Keep a ref: anchor and its target in the same data block — anchors resolve within the declaring block, and a cross-block anchor fails DDN-MK05.
  • Do not hand-type numerals into prose where an anchor exists; typed numbers drift, anchors do not.
